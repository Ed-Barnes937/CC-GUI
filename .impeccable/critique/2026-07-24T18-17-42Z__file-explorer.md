## Design Specificity Verdict

**Structurally on-brand, but the surface layer is a generic file picker — the Working Shell skeleton without the Working Shell fingerprints.**

Authored for CC-GUI: the interaction grammar is genuinely tailored (nnn single-column drill-down, vim `hjkl`, `/` filter, `.` hidden toggle, `@path`-into-the-terminal). Colors are fully token-based; the 21-token contract holds — the mechanical detector confirms zero raw hex/rgba in the fx block.

Where it reverts to category-interchangeable:
- **Mono-for-Data is entirely broken.** The design contract's most identity-defining rule reserves IBM Plex Mono for machine data (paths, counts, sizes, shortcuts). The fx CSS block (style.css:3349-3489) sets **no font-family at all** — crumbs, row names, `.fx-size`, `#fx-count`, `#fx-filter` all inherit IBM Plex **Sans** from body. A path browser that is *nothing but* machine data renders every path in the human typeface. Detector B confirms `--font-mono` exists (style.css:76) but is never applied here. Proportional digits also mean the size/count columns don't align.
- **Radius off-contract:** `.fx-row { border-radius: 6px }` (style.css:3433) — a one-off off the 7/10/12 + pill scale.
- **No transitions:** the 0.12s system norm is absent on `.fx-row`, `#fx-close`, `.fx-crumb` — the most-touched interaction (cursor/hover) snaps.
- **Focus treatment absent:** cursor is a background fill only (`.fx-row.cursor`, :3442); `#fx-list` is `outline:none` (:3425); the documented 2px-accent-outline norm is missing.
- **Accent overspent:** `.fx-row.dir .fx-name { color: var(--accent) }` (:3452) paints every directory accent — in a repo root that is most rows, so the scarce signal becomes the default.

**Deterministic scan:** `detect.mjs --json index.html` → exit 0, `[]`, zero findings. The mechanical detector is clean; every issue below is design-level judgment the detector doesn't cover. B's static read corroborates A on the token/mono/focus/radius facts precisely (no false positives, no disagreement).

**Visual overlays:** none — no browser driver in a native WKWebView app; no user-visible overlay was produced. Evidence is code + CSS.

## Overall Impression

The behavior is authored; the pixels are a theme reskin of a stock list. The keyboard instrument is genuinely good — complete, focus-disciplined, concurrency-safe. But on the one rule that most defines CC-GUI's identity (Mono-for-Data), a machine-data surface renders everything in Sans, and the single biggest functional flaw is that read errors masquerade as empty directories. Biggest opportunity: make it *look* like the instrument it already *behaves* like — mono the data, mark the cursor, tell the truth on failure.

## What's Working

1. **The keyboard grammar is real and complete** — `hjkl` + arrows, Home/End, `/` live filter, `.` hidden toggle, breadcrumb click-to-jump, and a filter mode that correctly routes printable keys vs commands (fileExplorer.ts:197-274). A properly designed expert instrument.
2. **Focus discipline on open/close** — `openExplorer` grabs list focus (:53); every exit (Esc, `×`, Cmd+E toggle) calls `focusTerminal()` (:187, :267, :278; main.ts:1298). Focus never gets lost between overlay and terminal.
3. **Stale-response guard** — `load()` captures `id` and bails if `sessionId` changed mid-flight (:70, :77). A correct, non-obvious concurrency detail most pickers get wrong.

## Priority Issues

- **[P0] Errors render as "Empty directory."** `fileExplorer.ts:80-83` sets `entries=[]` on catch; `render()` shows "Empty directory." (:97). Permission-denied, symlink loop, or I/O failure look identical to a genuinely empty folder, and the toast vanishes. *Why it matters:* the user trusts a lie and believes the folder is empty. *Fix:* track a `loadError` state; render a distinct `.fx-empty` variant ("Couldn't read this folder — <reason>") in `--danger`/`--warning`, not the neutral empty copy. *Suggested command:* `$impeccable harden`.
- **[P1] Mono-for-Data violated across the whole surface.** Crumbs, names, sizes, count, filter all inherit Sans (style.css:3349-3489 sets no mono family). *Why it matters:* the north star's most identity-defining rule, on a surface that is entirely machine data; also breaks numeric column alignment. *Fix:* apply `var(--font-mono)` to `#fx-crumbs`, `.fx-name`, `.fx-size`, `#fx-count`, `#fx-filter`; keep the human `#fx-hint` sentence in Sans. *Suggested command:* `$impeccable typeset`.
- **[P1] No visible keyboard-focus affordance; rows aren't real controls.** Cursor is background-fill only; `#fx-list` is `outline:none` (:3425); rows are plain `<div>` (fileExplorer.ts:101) with no `role`, `aria-activedescendant`, or `aria-selected`. *Why it matters:* fails the documented 2px-accent-outline focus norm and is invisible to assistive tech; cursor position isn't announced. *Fix:* add an inset 2px `--accent` outline to `.fx-row.cursor` alongside the fill; set `#fx-list` `role="listbox"`, rows `role="option"`, and `aria-activedescendant` to the cursor row id. *Suggested command:* `$impeccable audit`.
- **[P2] `/` and `.` are undiscoverable.** No affordance until invoked (`#fx-hidden-hint` populates only *after* `.` is pressed, :126). Dotfiles — high-value `@`-targets (CI, configs) — are hidden by default with no on-screen cue. *Why it matters:* recognition-over-recall fail; users miss the files they most want to reference. *Fix:* extend the static `#fx-hint` (index.html:112) to include `/ filter` and `. hidden`, or add persistent dim glyphs in the status bar. *Suggested command:* `$impeccable clarify`.
- **[P2] Non-destructive close hovers danger-red.** `#fx-close:hover { color: var(--danger) }` (style.css:3417). *Why it matters:* breaks state-color lockstep — red signals destruction; closing a picker destroys nothing. *Fix:* hover to `var(--text)`, matching the crumb hover two rules up. *Suggested command:* `$impeccable colorize`.

## Persona Red Flags

**Alex (Power User):**
- **No multi-select / batch.** `openEntry` writes one `@path ` and closes (:183-187). Referencing five files = open/pick/reopen ×5. The trailing space hints chaining was imagined, but instant-close kills it — the biggest efficiency miss for this tool's exact audience.
- **Filter is single-level substring, not recursive/fuzzy** (`visible()`, :62-66). Knowing the filename but not the folder still forces hand-navigation.
- **Blind write** — no echo of what was inserted before the overlay closes.

**Sam (Accessibility / Keyboard):**
- **Rows are `<div>` with no role and no accessible focus** (fileExplorer.ts:101; `#fx-list` `outline:none`). Screen readers get unlabeled div soup; cursor is a color fill only. Failing elements: `.fx-row`, `#fx-list`, `.fx-row.cursor`.
- **No `aria-activedescendant`/live region** — cursor movement and the `n/total` count change are silent to AT.
- **Linux open-path gap.** Cmd+E requires `e.metaKey && !e.ctrlKey` (main.ts:1293) with no Ctrl fallback (confirmed by grep). On Linux (ships `.deb`/`.AppImage`), Meta is the WM-reserved Super key, so a keyboard-first Linux user may have no working shortcut except the palette. Help lists only "Cmd+E" (help.ts:43).

**Riley (Stress Tester):**
- **Deep tree:** `#fx-crumbs` ellipsizes at the *end* (style.css:3379-3381), hiding the leaf (where you are) and keeping the root — backwards. Middle/RTL truncation would keep the current folder visible.
- **Huge dir:** no virtualization; `render()` rebuilds a `<div>` per entry with two listeners each on every cursor move (:100-122, :190-195). A `node_modules` builds thousands of nodes/listeners per keystroke, and no loading state masks the jank.
- **Symlink loop / permission-denied:** folds into the P0 — surfaces as "Empty directory."

## Minor Observations

- `render()` rebuilds the entire list (`innerHTML=""`) and re-binds listeners on every cursor move (:190-195). Cursor movement only needs a class swap.
- `fmtSize` uses `K`/`M` not `KB`/`MB` (:281-285) — terse and nnn-ish, on-brand, but check consistency with sizes elsewhere in the app.
- No file-type cue beyond the trailing `/` and dir-accent; a monochrome list of names is hard to scan by type.
- `#fx-count` shows `0` (not `0/0`) on an empty list (:129) — minor inconsistency with the `n/total` format.
- Hardcoded px font-sizes throughout the block (13/11/15px) rather than a type token/scale.

## Questions to Consider

1. If the entire job of this surface is emitting a machine path into a terminal, why render every path in the *human* typeface? Flip the default: mono everywhere, Sans only for the one hint sentence.
2. The tool is built for experts who reference files constantly — why does picking a file *end* the session instead of staging it? Would "Tab to stage, Enter to flush all as `@a @b @c`" serve Alex's real loop better than one-shot-and-close?
3. Given dotfiles (CI, configs) are among the most-referenced files in a repo, is hiding them by default right for *this* audience — or should hidden-shown be the default and `.` toggle them *off*?
